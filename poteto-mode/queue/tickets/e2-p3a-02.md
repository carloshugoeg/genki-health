## Implementation steps

1. Copy frozen `docs/plan/ddl/postgres.sql` into ordered migrations without re-inferring columns: `0001-core.sql` through `id_counter` (including the `receta_folio` seed row); `0002-identity.sql` for `rol`/`usuario`/`auth_session`; `0003-hospital-locks.sql` for `servicio`/`servicio_facturable`/`cama`/`admision`/`nota_evolucion`, their indexes, and `reporte_pacientes`. Apply against a disposable `genki_test_*` database in the schema suite.

2. Implement `mapper.ts` for TIMESTAMPTZ ↔ ISO-8601 Z strings, DATE ↔ `YYYY-MM-DD`, NUMERIC/DECIMAL ↔ JS number, and boolean. No SERIAL/BIGINT string conversion.

3. Implement `PostgresUnitOfWork` with pool max 5, READ COMMITTED, AsyncLocalStorage client scope, nested joins, COMMIT on success, ROLLBACK then release in finally on failure. Export `activePostgresClient()` for repositories and id allocation.

4. Implement `PostgresIdPort` so `nextInt('receta_folio')` atomically advances `id_counter` inside the current transaction. SQL row ids stay IDENTITY; do not invent document-style counters for paciente/consulta.

5. Implement `PostgresCatalogoRepository.list()` for the scoped institution: all municipios, active profesionales for that institution, active medicamentos; sort each list by id ascending.

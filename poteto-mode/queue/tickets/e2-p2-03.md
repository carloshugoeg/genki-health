## Implementation steps

1. Create shared `MemoryInstitutionState` with maps for pacientes, expedientes, responsables, consultas, diagnosticos, tratamientos, recetas, detalles, counters and catalogs. Empty maps are fine for collections later tickets fill.

2. Replace no-op `MemoryUnitOfWork` with promise-mutex outer writers, AsyncLocalStorage nested joins, clone-all-maps at outer entry, restore on failure, publish working snapshot only at commit. In-transaction reads see working state; outside readers miss partial writes.

3. Point `MemoryPacienteRepository` at the shared state (no private Maps). Return deep clones from reads/creates so callers cannot mutate storage. Keep existing method signatures; do not add list/guardian/consulta methods (P2-04/P2-06).

4. Wire `compose-memory` so one state backs UoW + pacientes for a set. Make `InstitutionAdapterRegistry` cache ONE `AdapterSet` per kind+institutionId for the process lifetime.

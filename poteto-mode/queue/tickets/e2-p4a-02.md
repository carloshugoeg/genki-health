## Implementation steps

1. Implement `MongoPacienteRepository` over institution-scoped `pacientes` / `expedientes` / `responsables` collections using existing `MongoUnitOfWork`, `MongoIdPort`, and mapper Int32/Date helpers. String `_id` keys only; no ObjectId DTO keys.

2. Atomic create: patient + optional guardians + expediente inside one session transaction; `afterWrite('afterPaciente')` after patient persist; pediatric kind requires ≥1 guardian and exactly one principal; non-pediatric rejects non-empty responsables; duplicate compares normalized `numero_documento` alone (unique index + `ClinicalError('duplicate_document')`).

3. Search/list: OR of exact documento, exact numero_expediente, literal case-insensitive name substring; escape regex metacharacters; sort by id_paciente ascending; page after estado filter; total is filtered total.

4. Archive updates expediente only (`estado=archivado`, `_rev` bump); never write archivado onto paciente; already archived → `already_archived`; missing/foreign → `not_found`.

5. Create `makeMongoClinicalHarness` on disposable `genki_test_mongodb_paciente` with failNext/counts/otherInstitution and stub consultas (full runner is E2-P4A-03). Use admin URI for schema install and test ownership; no shared/prod DB; no secrets in logs.

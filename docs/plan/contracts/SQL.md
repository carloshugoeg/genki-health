# Frozen C4 — SQL physical model and migration split

`ddl/postgres.sql` and `ddl/mysql.sql` are the exact full physical schema texts. Engine tickets copy them into runtime migrations; do not re-infer columns from Mermaid.

- PG16 signed INTEGER GENERATED BY DEFAULT AS IDENTITY; MySQL8.4 signed INTEGER AUTO_INCREMENT, InnoDB, utf8mb4_0900_as_ci. No SERIAL/BIGINT string conversion in this MVP. Surrogate ids remain JSON numbers.
- PostgreSQL TIMESTAMPTZ and MySQL DATETIME(3) with UTC connection; DATE stays YYYY-MM-DD. Monetary/quantity decimal values explicit NUMERIC/DECIMAL, converted to numbers for shared DTOs.
- Clinical FK deletes RESTRICT. There is no runtime delete privilege. Alternate patient key `(id_institucion,numero_documento)`, expediente patient UNIQUE, expediente number UNIQUE, recipe consultation UNIQUE, prescription detail compound primary key.
- Nullable principal uniqueness: PG partial unique index; MySQL STORED generated column of parent id when principal true else NULL, nullable UNIQUE. Generated helper columns never appear in DTO.
- MUNICIPIO is a real FK target. CAMA has tipo_cama and codigo_servicio, unique(id_servicio,codigo). NOTA_EVOLUCION has optional self-FK id_nota_anterior. These hospital-only entities are NOT added to MySQL, because source §7.5 excludes hospitalización.
- PROFESIONAL omits the three locked-B columns. Its colegiado is nullable UNIQUE with a nonblank CHECK. Because no tipo_personal FK exists by lock, conditional qualification is checked from seed professional-type metadata before insert; no unrestricted professional CRUD exists. No invented hidden FK.
- Runtime schema is the MVP plus minimal hospital lock appendix, not all modeled tables. CITA is not implemented: consulta.id_cita nullable CHECK IS NULL, no dangling FK. Full appointments and other deferred entities require future additive migrations. No false claim the full model is implemented.
- PG migration split:0001 through id_counter;0002 rol/usuario/auth_session;0003 servicio/servicio_facturable/cama/admision/nota_evolucion and report view. MySQL0001 contains full C4b. Schema migration ledger is infrastructure, owned by migration role; checksums immutable after applied.
- `numero_expediente` must have its final EXP-id before commit. PostgreSQL reserves its identity sequence value then inserts explicit id (BY DEFAULT); MySQL inserts a unique temporary TMP-P-patient-id then updates to EXP-insertId in same transaction. Temporary values never escape transaction.
- Identity data only Hospital PostgreSQL. Every other SQL/document store has copied institution/catalog metadata, not password/hash/JWT user stores.

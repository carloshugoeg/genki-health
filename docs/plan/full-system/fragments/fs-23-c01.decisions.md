# FS-23-C01 decisions

## D1 — Thin executeOp + persistence port behind ChargesRepositoryPort

- **Decision:** `executeOp68/69` delegate to `context.modules.charges.opNN`. `createChargesPort(getContext, store)` closes over a `ChargesPersistence` implemented by `MemoryChargesStore`. Domain owns schema/role/tariff/projection rules.
- **Why:** Matches F1 opNN port naming for cross-module reuse while keeping billing/role rules out of the engine adapter (PORTS-LANES). Avoids application→adapter imports (depcruise).
- **Rejected:** Fat memory adapter owning role/tariff rules; HTTP-status assertions in core tests; editing foundation `context.ts` / package `pregate` in this PR.
- **ADR links:** FS-008 (money/idempotency), FS-012 (module fragment ownership).

## D2 — clave_evento uniqueness via extension side table + COMANDO_IDEMPOTENTE

- **Decision:** Persist `cargo_clave_evento` map for unique source events; store HTTP/idempotency replay in `comandos_idempotentes` with SHA-256 `hash_request`. Additive `clave_evento` is not on frozen `CARGO` TS interface from foundation schema.
- **Why:** schema-additions.json adds `clave_evento`; F2 requires idempotent mutation replay; core must not edit foundation `schema.ts`.
- **Rejected:** Inventing CARGO field edits in `shared/src/full/schema.ts`; silent overwrite on duplicate clave.

## D3 — Pregate absence recorded, not invented

- **Decision:** Treat `bash scripts/validate.sh` + module memory suite as the applicable green gate for this isolated PR. Do not add `pregate` script/lockfile edits.
- **Why:** Ticket file ownership forbids package/CI/toolchain paths; FS-TOOLCHAIN owns pregate.
- **Rejected:** Adding a local `pregate` alias in this module PR.
